4. Deep Dive: Core Engines & Data Flows

4.1 Socratic AI Tutoring Architecture (NVIDIA NIM)

When a learner requests guidance, the frontend opens an asynchronous WebSocket connection to /api/v1/tutor/ws, transmitting problem context and the user's current code buffer.

The 3-Card Socratic Output Structure:
  • 💡 Observation: Identifies algorithmic logic and edge cases in the user's code.
  • 🎯 Probing Question: Prompts the student to discover the next optimization step.
  • ⚡ Actionable Hint: Provides a minimal, non-spoiling hint to unblock progress.

7. Technical Q&A Cheat Sheet (For Judges & Evaluators)

Q1: Why did you choose NVIDIA NIM over standard OpenAI endpoints?
Answer: NVIDIA NIM delivers dedicated, hardware-accelerated low-latency inference endpoints, which is critical for real-time WebSocket token streaming in an interactive IDE. We run meta/llama-3.3-70b-instruct to achieve frontier-grade algorithmic reasoning without proprietary lock-in.
Q2: How do you guarantee the AI doesn't spoil solutions?
Answer: We implement multi-layered guardrails: a strict Socratic system prompt forbidding code blocks, a Python token cleaner stripping chain-of-thought artifacts, and a frontend parser that enforces 3-part micro-cards (Observation, Probing Question, Actionable Hint).
Q3: How is user code executed safely?
Answer: Submissions pass through an AST validator to reject unsafe system calls and malicious imports, followed by execution inside an isolated asynchronous Python subprocess with hard 5.0-second CPU limits and memory bounds.
Q4: How does the system scale under high traffic?
Answer: The backend is built on FastAPI and Uvicorn with fully asynchronous I/O. Database operations use asyncpg connection pooling with Supabase's IPv4 pooler, allowing hundreds of concurrent WebSocket tutoring sessions per lightweight container.
